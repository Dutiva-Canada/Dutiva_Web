01 · System context

Two services. The consuming app (Dutiva--Redesign-, React 19 + Vite + Tailwind v4) owns the chat UI, the Compliance Workspace, thread state and i18n. The engine (dutiva-advisor-engine, Express + Qwen) owns routing, retrieval, validation and the response contract. They talk over one HTTP call.

Consuming app renders
conversationalResponse in chat · workspace payload in the panel · gated on route.*Allowed.
→
Engine returns
POST /api/advisor/respond → route · jurisdiction · risk · professionalReview · workspace · webSearch · quality · isCrisis.
Non-negotiable principles
  • Obey the gates. Never render workspace / legal basis / retrieval / documents / web results when the matching route.*Allowed is false. Build a fresh context per turn — never carry a prior turn's structured data forward.
  • Jurisdiction is never assumed. Province defaults to null; surface the collect-jurisdiction prompt when status is unknown; show conflict warnings.
  • Disclaimer always ships near Advisor output, generated docs and CTAs. Not legal advice.
  • Bilingual EN/FR parity is enforced by the type system — every user string is a { en, fr } pair.
  • Crisis intercepts everything. isCrisis surfaces maintained resources; no HR content, gates all off, cannot be overridden by mode.

05 · Advisor memory

A durable memory layer so the Advisor carries context between sessions — about a person, a conversation thread, and a case. Prototyped in Advisor Memory.dc.html: a person profile panel, case memory + timeline, inline chat recall with sources, the workspace “What I know” section, and a governed memory manager.

Memory ≠ carried-forward turn state

Memory is a facts-and-context layer, retrieved and injected into the prompt as inputs. It never carries a prior turn’s structured output forward — route, risk, legal basis, citations, gates and isCrisis are still computed fresh every turn (Principle 1 holds). Memory feeds the turn; it never replays a past decision.

Person memory
Facts about an employee/candidate, carried into every case and chat about them. Scope person:{id}.
Thread memory
What was said earlier in one conversation, so follow-ups resolve against it. Scope thread:{id}.
Case memory
A case’s summary, decisions and open threads — persisted across the many sessions it takes to resolve. Scope case:{id}.
Capture & confidence
  • Advisor extracts candidate facts per turn — automatically, each linked to its turn or document.
  • Two states only: Confirmed (authoritative source) vs Inferred (Advisor-derived).
  • Inferred is never treated as fact until a human confirms; confirming promotes it.
  • Correct/forget any time — first-class actions, not buried admin.
Governance (non-negotiable)
  • Provenance on every fact: source, learned + last-confirmed dates.
  • Visibility scope: HR team / case + counsel / restricted (comp, health).
  • Retention TTLs by scope; wellbeing & personal notes auto-forget at 12 months.
  • PIPEDA · Québec Law 25: access, correction & erasure; forget honours those requests (source untouched).
  • Every add / edit / forget is audit-logged with who + when.
Memory workstreams

✓ Forget → the fact stops being retrieved, its source stays intact, and an audit entry is written.

06 · Quality gate
  • Engine evals/ regression suite green (routing + screenshot cases).
  • App npm run check (tsc strict + oxlint + vitest) on every commit.
  • Contract tests assert gate → UI: a false gate must never paint its section.
  • Bilingual snapshot: EN & FR render for every route.
  • a11y: focus-visible, ≥44px hit targets, aria-live on streamed replies.
07 · Observability & risk
  • Log route.intent, latency, gate decisions, quality warnings — never PII or message bodies.
  • Web search is off by default; PII is redacted before any query leaves the engine.
  • Rate-limit + 30s timeout already in the engine; add a client fallback turn.
  • Risk: FR guidance corpus is not production-validated — keep FR gated to routing/LLM until reviewed.
